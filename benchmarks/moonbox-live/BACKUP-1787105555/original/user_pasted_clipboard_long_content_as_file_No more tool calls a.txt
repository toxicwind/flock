THE ACTUAL gRPC ERROR

`message size %d exceeds sendMaxBytes %d` — found in the portal binary strings.

`resource_exhausted: insufficient balance` — the gateway response when quota is burned out.

These are the same error chain. gRPC status code `RESOURCE_EXHAUSTED` (8) covers both:
- Message size exceeding `sendMaxBytes` 
- Billing/quota exhaustion

---

WHAT BROKE (The Cascade)

```
/mnt/agents/.agents/plugins ──symlink──► /mnt/portal-overlay/.agents/plugins
                                              │
                                              ▼
                                    portal FUSE (fuse.portal)
                                              │
                                              ▼
                              gRPC/Connect-RPC to kimi-api-sandbox.msh.team/apiv2
                                              │
                                              ▼
                                    sendMaxBytes limit hit on large files
                                              │
                                              ▼
                                    Retries + repeated large reads
                                              │
                                              ▼
                                    Quota burned → "insufficient balance"
                                              │
                                              ▼
                                    403 resource_exhausted from gateway
```

The portal is a FUSE filesystem (`/usr/local/bin/portal -http-bind -allow-other -env prod -gateway-addr https://kimi-api-sandbox.msh.team/apiv2 /mnt/portal-overlay`). Every file read through `/mnt/portal-overlay` becomes a gRPC request. The symlinks force local drive9 files through the portal's metered gateway connection.

The `max_read=1048576` (1MB) on the FUSE mount means large files get chunked, but the portal's internal `sendMaxBytes` is smaller — causing failures, retries, and quota drain.

RESTORE THE ENDPOINT (No Code Changes)

```bash
rm /mnt/agents/.agents/plugins
rm /mnt/agents/.user/auth
rm /mnt/agents/.user/skills
rm /mnt/agents/.websites-templates
```

This stops local file operations from transiting the portal FUSE and burning gateway quota.


This resets the TLS connection to `172.29.160.117:443` and clears any stuck gRPC streams.

WHY THE SDK "STORAGE FULL" DOCUMENT IS RELATED

The uploaded document correctly identified the SDK bug (`ToolResponse` wrapping plain-string errors as `is_success=True`). But that bug was the accelerant, not the root cause. The root cause is the portal FUSE symlink loop forcing every local file operation through the metered gateway.

The `generate_image` / `generate_video` calls from the document would burn quota even faster when their outputs get written back through the portal FUSE mount. But the quota was already being drained by the symlink loop before any generation calls.
