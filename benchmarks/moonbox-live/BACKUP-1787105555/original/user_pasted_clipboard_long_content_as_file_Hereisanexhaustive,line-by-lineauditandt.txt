Part 1: How to Use Completions (Including Unlimited Streaming)
The client supports both OpenAI-compatible (/v1/chat/completions) and Anthropic-compatible (/v1/messages) APIs, with native Server-Sent Events (SSE) streaming.
1. Standard Synchronous Chat Completion
from agent_gw import AgentGwClient

with AgentGwClient(api_key="sk-...", base_url="https://agent-gw-dev.dev.kimi.team/coding") as client:
    response = client.chat_completion(
        model="kimi-k1.5",
        messages=[{"role": "user", "content": "Write a Python script for web scraping."}],
        temperature=0.7,
    )
    print(response["choices"][0]["message"]["content"])

2. Unlimited SSE Streaming Completions
When stream=True is passed, chat_completion() returns a generator yielding parsed JSON SSE chunks. Because long-running agent reasoning or multi-turn coding outputs can take extended time, set timeout=None or a large float value on the client call to allow unlimited streaming without client-side timeout drops.
with AgentGwClient(api_key="sk-...", timeout=None) as client:
    stream_iterator = client.chat_completion(
        model="kimi-k1.5",
        messages=[{"role": "user", "content": "Refactor a 10,000-line codebase."}],
        stream=True,
    )

    for chunk in stream_iterator:
        # Check for standard OpenAI delta content
        choices = chunk.get("choices", [])
        if choices:
            delta = choices[0].get("delta", {}).get("content", "")
            print(delta, end="", flush=True)

3. Anthropic Messages API Format (/v1/messages)
response = client.messages(
    model="claude-3-5-sonnet",
    messages=[{"role": "user", "content": "Hello!"}],
    max_tokens=1024,
)

Part 3: Most Standout, Obtuse, and "Whoa This Is Emergent" Discoveries
1. Security & Traffic Engineering: Zero-Proxy Direct S3 Offloading
In download_storage() (lines 763–787):
# 直接打 signed_url（公网，不经网关、不带 apikey）。用 session.request 而非 self._request，避免附加 Authorization 等网关头。
resp = self._session.request("GET", signed_url, ...)

 * Why it's clever: Instead of proxying heavy media files (images, video, audio) through agent-gw, the gateway returns a signed_url. The client then bypasses the gateway entirely, hitting the CDN/S3 object storage, which responds with a 307 Temporary Redirect.
 * Security Precision: The code explicitly avoids calling self._request() and uses a raw session.request() to prevent sending the Authorization: Bearer <KIMI_API_KEY> header to S3/CDN endpoints, avoiding credential leakage to cloud storage providers.
2. Dual-Storage Backend Division (OpenGW vs kimifs)
The SDK maintains two separate file upload endpoints that target completely different backend architectures:
 * upload_file() (/v1/files): Passthrough to OpenGW (OpenAI file API style). It is strictly write-only (POST), with no support for LIST, GET, DELETE, or reading content.
 * upload_storage() (/v1/storage): Backed by kimifs (Kimi File System). This returns a public signed_url specifically designed to feed reference assets into image (generate_image) and video (generate_video) pipelines.
3. Tonghuashun iFind Financial Terminal Integration (get_stock_realtime_price)
The gateway includes built-in integration with iFind (China's leading institutional financial data terminal):
params: Dict[str, Any] = {"ticker": ticker, "time": time, "type": type}
if file_path:
    params["file_path"] = file_path # Injects local file path for iFind output

 * Timezone Rules: US stock queries require US Eastern Time (ET), while Chinese A-shares (.SH, .SZ) require Beijing Time (CST/BJT).
 * Local File Injection: Allows specifying a local file_path (e.g. /tmp/foo.json) for temporary financial data export.
4. Custom Context Headers (X-Kimi-Chat-Id and X-Kimi-Skill)
All HTTP requests automatically attach custom headers if present:
 * X-Kimi-Chat-Id: Tracks multi-turn session identity across agent execution nodes.
 * X-Kimi-Skill: Identifies active skill modules/tools loaded by the agent runner.
